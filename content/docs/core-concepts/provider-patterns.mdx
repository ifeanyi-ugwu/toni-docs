---
title: Provider Patterns
description: Value providers, factory providers, alias providers, and token providers — all the ways to put things into the DI container.
---

Beyond plain injectable services, Toni supports several provider patterns for registering non-struct values, computed results, async-initialized resources, and alternate names for existing providers.

<Bridge>
These map directly to NestJS's custom provider syntax:

| NestJS | Toni |
|--------|------|
| `{ provide: 'TOKEN', useValue: value }` | `provider_value!("TOKEN", value)` |
| `{ provide: 'TOKEN', useFactory: () => fn() }` | `provider_factory!("TOKEN", \|\| fn())` |
| `{ provide: 'TOKEN', useFactory: async (dep) => fn(dep), inject: [Dep] }` | `provider_factory!("TOKEN", async \|dep: Dep\| fn(dep))` |
| `{ provide: 'TOKEN', useExisting: ExistingService }` | `provider_alias!("TOKEN", ExistingService)` |
| `{ provide: TOKEN, useClass: ServiceClass }` | `provider_token!("TOKEN", ServiceClass)` |
</Bridge>

## Service providers (the default)

The most common pattern — list the struct name:

```rust
#[module(
    providers: [UsersService, AuthService],
)]
pub struct AppModule;
```

Both `UsersService` and `AuthService` must be annotated with `#[injectable]`. The container builds each one from its fields — `#[inject]` fields are resolved from the DI graph, `#[default(expr)]` fields get their expression — or through a `#[new]`-tagged constructor when one exists. `#[new]` is the right tool when construction needs logic or a dependency is consumed without being stored; field injection covers everything else. See [Services & Providers](/docs/core-concepts/services).

## Value providers

Inject a static, pre-computed value under a string token or a type token:

```rust
#[module(
    providers: [
        provider_value!("APP_NAME", "MyApp".to_string()),
        provider_value!("PORT", 3000_u16),
        provider_value!(Duration, Duration::from_secs(60)),   // type as token
    ],
)]
pub struct AppModule;
```

Inject by token in a service field using the `#[inject("TOKEN")]` attribute:

```rust
#[injectable]
pub struct AppInfo {
    #[inject("APP_NAME")]
    name: String,

    #[inject("PORT")]
    port: u16,

    // a type registered under a custom token
    #[inject("PRIMARY_CONFIG")]
    config: ConfigService,
}
```

When no token is specified, `#[inject]` resolves by the field's type. The `#[inject("TOKEN")]` form resolves by the explicit token string.

## Factory providers

Run a closure to produce a value, with optional dependencies:

```rust
#[module(
    providers: [
        // No dependencies
        provider_factory!("REQUEST_ID", || {
            format!("req_{}", std::time::SystemTime::now()
                .duration_since(std::time::UNIX_EPOCH).unwrap().as_millis())
        }),

        // With typed dependencies
        provider_factory!("APP_INFO", |config: ConfigService| {
            format!("App running in {} mode", config.get_env())
        }),

        // Async factory — detected by the `async` keyword
        provider_factory!("ASYNC_STATUS", async |logger: LoggerService| {
            logger.log("System initialized")
        }),
    ],
)]
pub struct AppModule;
```

Dependencies listed in the closure signature are resolved from the module's DI scope before the factory runs.

## Alias providers

Create an alternate token pointing to an existing provider. The same instance is returned for both tokens:

```rust
#[module(
    providers: [
        ConfigService,
        provider_alias!("Config", ConfigService),       // token → type
        provider_alias!("APP_PORT", "PORT"),             // token → token
    ],
)]
pub struct AppModule;
```

Useful when consuming code uses a different token name than the provider's type.

## Token providers

Register a type under a custom string token. Unlike listing the type in `providers`, this does **not** create the default type-token entry — the custom token is the only way to reach it:

```rust
#[module(
    providers: [
        provider_token!("PRIMARY_DB", DatabaseService),
        provider_token!("REPLICA_DB", ReplicaDatabaseService),
    ],
)]
pub struct AppModule;
```

## The `provide!` macro (unified)

`provide!` covers all of the above with one entry point. The first argument is the token; the second is auto-detected — a closure or async block becomes a factory, anything else a value:

```rust
#[module(
    providers: [
        provide!("API_KEY", "secret_key".to_string()),     // value
        provide!("MAX_CONNECTIONS", || 100_i32),           // factory
        provide!("LOGGER", |config: ConfigService| {       // factory with dep
            Logger::for_env(config.get_env())
        }),
    ],
)]
pub struct AppModule;
```

Marker functions make the variant explicit, and are the only spelling for aliases and token providers:

```rust
provide!("EXPLICIT_VALUE", value("explicit".to_string())),  // value provider
provide!("EXPLICIT_FACTORY", factory(|| compute())),        // factory provider
provide!("CACHE_ALIAS", existing(CacheService)),            // alias provider
provide!("PRIMARY_DB", provider(DatabaseService)),          // token provider
```

## Multi-providers

Several `provide!` entries can contribute to the same token; the contributions are collected into a `Vec`. Add `multi(Trait)` naming the trait every contribution implements:

```rust
#[module(
    providers: [
        PluginA,
        PluginB,
        provide!("PLUGINS", PluginA, multi(Plugin)),
        provide!("PLUGINS", PluginB, multi(Plugin)),
        PluginRegistry,
    ],
)]
pub struct AppModule;
```

The consumer injects the collection as `Vec<Arc<dyn Trait>>`:

```rust
use std::sync::Arc;

#[injectable]
pub struct PluginRegistry {
    #[inject("PLUGINS")]
    plugins: Vec<Arc<dyn Plugin>>,
}
```

`multi(Plugin)` is shorthand for `multi(dyn Plugin + Send + Sync)`. Contributions can be type paths, factory closures, or `existing(...)` references; a token with no contributions injects an empty `Vec`.

## Exporting custom-token providers

The `exports` list in `#[module]` accepts type names, so type-token providers export directly:

```rust
#[module(
    providers: [DatabaseService],
    exports: [DatabaseService],
)]
pub struct DatabaseModule;
```

String-token providers are exported from a [dynamic module](/docs/core-concepts/modules#dynamic-modules) via `export_token`:

```rust
DynamicModule::builder("ConfigModule")
    .provider(/* value provider factory */)
    .export_token("DB_URL")
    .build()
```
