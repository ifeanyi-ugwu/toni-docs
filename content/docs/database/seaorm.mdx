`toni-seaorm` provides a `SeaOrmModule` that connects to a database at startup and makes `DatabaseConnection` available to any provider in the application via the global DI scope.

<Bridge>
This follows the same pattern as NestJS's `TypeOrmModule.forRoot()` — one call in the root module, then inject the connection handle anywhere without needing to import the database module into each feature module.
</Bridge>

## Setup

Add the dependency:

```toml
[dependencies]
toni = "0.2"
toni-seaorm = "0.1"
sea-orm = { version = "1", features = ["sqlx-postgres", "runtime-tokio-rustls"] }
```

## Registration

Call `SeaOrmModule::for_root` in your root module's `imports`:

```rust
use toni_seaorm::SeaOrmModule;

#[module(
    imports: [
        SeaOrmModule::for_root("postgres://user:pass@localhost/mydb"),
    ],
    controllers: [UsersController],
    providers: [UsersService],
)]
pub struct AppModule;
```

`for_root` returns a **global** `DynamicModule`. `DatabaseConnection` is available to every module in the application without needing to import `SeaOrmModule` into each feature module.

The connection is established at startup and panics on failure, so a bad URL or unreachable host surfaces immediately rather than on the first query.

## Injecting the connection

The default connection is injected by type — no token string needed:

```rust
use sea_orm::DatabaseConnection;

#[injectable]
pub struct UsersService {
    #[inject]
    db: DatabaseConnection,
}

impl UsersService {
    pub async fn find_all(&self) -> Result<Vec<user::Model>, sea_orm::DbErr> {
        user::Entity::find().all(&self.db).await
    }

    pub async fn find_by_id(&self, id: i32) -> Result<Option<user::Model>, sea_orm::DbErr> {
        user::Entity::find_by_id(id).one(&self.db).await
    }
}
```

`DatabaseConnection` is `Clone` — it wraps a connection pool internally. Each inject gets a clone that shares the same pool.

## Multiple connections

`for_root_named` registers an additional connection under a string name:

```rust
#[module(
    imports: [
        SeaOrmModule::for_root("postgres://localhost/app"),
        SeaOrmModule::for_root_named("analytics", "postgres://localhost/analytics"),
    ],
)]
pub struct AppModule;
```

A named connection is injected by its name token:

```rust
#[injectable]
pub struct ReportsService {
    #[inject]
    db: DatabaseConnection,          // default connection
    #[inject("analytics")]
    analytics: DatabaseConnection,   // named connection
}
```

Names are global identifiers — two connections cannot share one, even across different integration crates. Two unnamed `for_root` calls with different URLs are refused at startup (one would silently shadow the other), so every connection past the first needs a name. A named connection registers the connection only; the `health` feature's indicator stays on the default `for_root` connection.

## Using env vars

Combine with `toni-config` or `std::env::var` to avoid hardcoding credentials:

```rust
#[module(
    imports: [
        SeaOrmModule::for_root(std::env::var("DATABASE_URL").expect("DATABASE_URL must be set")),
    ],
)]
pub struct AppModule;
```

Or with a typed config. A `DynamicModule` is not a provider — it can't be produced by a factory at injection time, so the URL must be known when the module tree is built. Load the config first, then pass the value to `for_root`:

```rust
use toni_config::{Config, ConfigModule};

#[derive(Config, Clone)]
pub struct AppConfig {
    #[env("DATABASE_URL")]
    pub database_url: String,
}

fn database_module() -> toni::DynamicModule {
    let config = ConfigModule::<AppConfig>::from_env()
        .expect("invalid configuration");
    SeaOrmModule::for_root(config.get_ref().database_url.clone())
}

#[module(
    imports: [database_module()],
)]
pub struct AppModule;
```

## Shutdown

`SeaOrmModule` closes the database connection gracefully when `app.close()` is called or the application shuts down. In-flight queries are allowed to complete before the connection is closed.

## Health checks

Enable the `health` feature to have `for_root` also register a `SeaOrmHealthIndicator`, which exposes `ping_check(key)` for use with `toni-terminus`. See [Health checks](/docs/techniques/health).

## API reference

```rust
use toni_seaorm::SeaOrmModule;

SeaOrmModule::for_root(url: impl Into<String>) -> DynamicModule
SeaOrmModule::for_root_named(name: impl Into<String>, url: impl Into<String>) -> DynamicModule
```

The returned `DynamicModule`:
- is named `"SeaOrmModule"`
- provides `sea_orm::DatabaseConnection` — by type for `for_root`, under the `name` token for `for_root_named`
- exports `DatabaseConnection`
- is **global** (no need to import into feature modules)
