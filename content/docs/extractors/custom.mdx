---
title: Custom Extractors
description: Implement FromRequestParts or FromRequest to extract any data from incoming requests with full type safety.
---

When the built-in extractors don't cover your case, implement one of the two extraction traits on your own type. The framework calls it automatically whenever the type appears in a handler signature.

<Bridge>
Custom extractors are Toni's equivalent of NestJS's `createParamDecorator()`. Where NestJS resolves `@CurrentUser()` at runtime through reflection, Toni resolves `user: CurrentUser` at compile time through a trait impl — same ergonomics, no hidden magic.
</Bridge>

## Two traits

```rust
/// Sync, reads metadata only (headers, URI, extensions, path/query params).
/// Safe to use several per handler.
pub trait FromRequestParts: Sized {
    type Error: std::fmt::Display;

    fn from_request_parts(parts: &RequestPart) -> Result<Self, Self::Error>;
}

/// Async, consumes the owned request (and potentially its body).
/// At most one body-consuming extractor per handler.
pub trait FromRequest: Sized {
    type Error: std::fmt::Display + Send + Sync + 'static;

    fn from_request(
        req: HttpRequest,
    ) -> impl std::future::Future<Output = Result<Self, Self::Error>> + Send;
}
```

Pick by what you read:

- **Headers, cookies, path params, query params, extensions** → `FromRequestParts`. It receives `&RequestPart` (a borrow of the request metadata) and never touches the body.
- **The request body** → `FromRequest`. It receives the owned `HttpRequest` and may drain the body — which is why only one such extractor fits per handler.

Every `FromRequestParts` type gets `FromRequest` for free via a blanket impl that discards the body, so both kinds mix freely in handler signatures.

When an extractor returns `Err`, the handler never runs and the client receives an inline 400: `{"error": "Extraction failed", "details": "<your Error's Display output>"}`. Wrapping the parameter in `Option<T>` turns that failure into `None` instead.

## Example: Bearer token

A header extractor — metadata only, so `FromRequestParts`:

```rust
use std::fmt;
use toni::FromRequestParts;
use toni::http_helpers::RequestPart;

#[derive(Debug, Clone)]
pub struct BearerToken(pub String);

#[derive(Debug)]
pub enum TokenError {
    Missing,
    InvalidFormat,
}

impl fmt::Display for TokenError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            TokenError::Missing => write!(f, "Authorization header missing"),
            TokenError::InvalidFormat => write!(f, "Authorization header must be 'Bearer <token>'"),
        }
    }
}

impl FromRequestParts for BearerToken {
    type Error = TokenError;

    fn from_request_parts(parts: &RequestPart) -> Result<Self, Self::Error> {
        let auth_header = parts
            .headers
            .get("authorization")
            .and_then(|v| v.to_str().ok())
            .ok_or(TokenError::Missing)?;

        let token = auth_header
            .strip_prefix("Bearer ")
            .ok_or(TokenError::InvalidFormat)?
            .to_string();

        Ok(BearerToken(token))
    }
}

// Use it exactly like any built-in extractor
#[get("/token")]
fn get_token(&self, BearerToken(token): BearerToken) -> Body {
    Body::json(serde_json::json!({ "token": token, "length": token.len() }))
}
```

`parts.headers` is an `http::HeaderMap` — values are `HeaderValue`, so read them with `.get(name).and_then(|v| v.to_str().ok())`.

## Example: Client IP

Same pattern, different headers — respects proxies via `X-Forwarded-For`:

```rust
#[derive(Debug, Clone)]
pub struct ClientIp(pub String);

impl FromRequestParts for ClientIp {
    type Error = String;

    fn from_request_parts(parts: &RequestPart) -> Result<Self, Self::Error> {
        if let Some(forwarded) = parts
            .headers
            .get("x-forwarded-for")
            .and_then(|v| v.to_str().ok())
        {
            if let Some(ip) = forwarded.split(',').next() {
                return Ok(ClientIp(ip.trim().to_string()));
            }
        }

        if let Some(real_ip) = parts.headers.get("x-real-ip").and_then(|v| v.to_str().ok()) {
            return Ok(ClientIp(real_ip.to_string()));
        }

        Err("No IP address headers found".to_string())
    }
}
```

## Composing extractors

A custom extractor can call other extractors. Built-ins like `Query` implement `FromRequestParts`, so a wrapper stays sync and body-free:

```rust
use serde::Deserialize;
use toni::FromRequestParts;
use toni::extractors::Query;
use toni::http_helpers::RequestPart;

pub struct Pagination {
    pub page: u32,
    pub per_page: u32,
    pub offset: u32,
}

impl FromRequestParts for Pagination {
    type Error = String;

    fn from_request_parts(parts: &RequestPart) -> Result<Self, Self::Error> {
        #[derive(Deserialize, Default)]
        struct RawPagination {
            page: Option<u32>,
            per_page: Option<u32>,
        }

        let Query(raw) = Query::<RawPagination>::from_request_parts(parts)
            .map_err(|e| e.to_string())?;

        let page = raw.page.unwrap_or(1).max(1);
        let per_page = raw.per_page.unwrap_or(20).min(100);
        let offset = (page - 1) * per_page;

        Ok(Pagination { page, per_page, offset })
    }
}

#[get("/")]
fn list(&self, pagination: Pagination) -> Body {
    let items = self.service.find_page(pagination.offset, pagination.per_page);
    Body::json(serde_json::json!({
        "items": items,
        "page": pagination.page,
        "per_page": pagination.per_page,
    }))
}
```

The same composition builds aggregate extractors — an `AuthContext` that combines a `CurrentUser`, `ClientIp`, and user agent into one parameter is three `from_request_parts` calls on the same `parts`.

## Body-consuming extractors

Implement `FromRequest` when you need the body. Decompose the request with `into_parts()`, then collect or stream the body:

```rust
use toni::FromRequest;
use toni::http_helpers::HttpRequest;

/// Deserializes the body as YAML (via the `serde_yaml` crate).
pub struct Yaml<T>(pub T);

impl<T: serde::de::DeserializeOwned + Send> FromRequest for Yaml<T> {
    type Error = String;

    async fn from_request(req: HttpRequest) -> Result<Self, Self::Error> {
        let (_parts, body) = req.into_parts();
        let bytes = body
            .collect()
            .await
            .map_err(|e| format!("Failed to read body: {e}"))?;
        let value = serde_yaml::from_slice(&bytes).map_err(|e| format!("Invalid YAML: {e}"))?;
        Ok(Yaml(value))
    }
}
```

A `FromRequest` extractor that reads the body counts as the handler's single body consumer, exactly like `Json` or `Bytes`.

## Validation support

`Validated<E>` works with any extractor that implements `ValidatableExtractor`, which exposes the inner value for the `validator` crate:

```rust
pub trait ValidatableExtractor {
    type Inner: validator::Validate;

    fn get_inner(&self) -> &Self::Inner;
}
```

Implement it on your extractor to opt in:

```rust
use toni::extractors::ValidatableExtractor;

impl<T: validator::Validate> ValidatableExtractor for Yaml<T> {
    type Inner = T;

    fn get_inner(&self) -> &Self::Inner {
        &self.0
    }
}

// Now this validates the deserialized value before the handler runs:
// Validated(Yaml(dto)): Validated<Yaml<CreateUserDto>>
```

On failure, `Validated` produces `ValidationError` (exported alongside `ValidatableExtractor` from `toni::extractors`): `ExtractionError` when the inner extractor failed, `ValidationFailed` carrying the `validator::ValidationErrors` when a rule was violated. Both surface as the standard 400 extraction response.
