title: Custom Extractors
description: Implement FromContext to extract any data from incoming requests with full type safety.

When the built-in extractors don't cover your case, implement the extraction trait on your own type. The framework calls it automatically whenever the type appears in a handler signature.

## One trait

Every extractor — built-in or custom, on any transport — implements `FromContext`:

```rust
pub trait FromContext<C: HandlerContext>: Sized {
    type Error: fmt::Display;

    fn extract(ctx: &C) -> impl Future<Output = Result<Self, Self::Error>> + Send;
}
```

`C` is the context the extractor reads from — `HttpContext` for HTTP handlers. An extractor names the contexts it is valid for by which impls it carries, so reaching for an HTTP extractor in a WebSocket handler is a trait-bound error, not a runtime surprise.

On HTTP there are two shapes, and which one you write decides whether the extractor touches the body:

- **Metadata** — headers, path params, query params, extensions. Borrow the request parts with `ctx.request()`, which returns `&RequestPart` and leaves the body alone. Any number of these can run on one handler.
- **The body** — call `take_body::<Self>(ctx)?`, which yields the owned `HttpRequest` exactly once. A second body read fails with `BodyAlreadyRead`.

When an extractor returns `Err`, the handler never runs and the client receives an inline 400: `{"error": "Extraction failed", "details": "<your Error's Display output>"}`. Wrapping the parameter in `Option<T>` turns that failure into `None` instead.

## Example: Bearer token

A header extractor — metadata only, so it borrows `ctx.request()`:

```rust
use std::fmt;
use toni::{FromContext, HttpContext};

#[derive(Debug, Clone)]
pub struct BearerToken(pub String);

#[derive(Debug)]
pub enum TokenError {
    Missing,
    InvalidFormat,
}

impl fmt::Display for TokenError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            TokenError::Missing => write!(f, "Authorization header missing"),
            TokenError::InvalidFormat => write!(f, "Authorization header must be 'Bearer <token>'"),
        }
    }
}

impl FromContext<HttpContext> for BearerToken {
    type Error = TokenError;

    async fn extract(ctx: &HttpContext) -> Result<Self, Self::Error> {
        let auth_header = ctx
            .request()
            .headers
            .get("authorization")
            .and_then(|v| v.to_str().ok())
            .ok_or(TokenError::Missing)?;

        let token = auth_header
            .strip_prefix("Bearer ")
            .ok_or(TokenError::InvalidFormat)?
            .to_string();

        Ok(BearerToken(token))
    }
}

// Use it exactly like any built-in extractor
#[get("/token")]
fn get_token(&self, BearerToken(token): BearerToken) -> Body {
    Body::json(serde_json::json!({ "token": token, "length": token.len() }))
}
```

`ctx.request().headers` is an `http::HeaderMap` — values are `HeaderValue`, so read them with `.get(name).and_then(|v| v.to_str().ok())`.

A metadata extractor's `extract` is `async` with nothing to await — the trait has one shape for every extractor, and only body extractors actually await anything.

## Composing extractors

A custom extractor can call other extractors on the same context. Built-ins like `Query` are metadata extractors, so a wrapper around them stays body-free:

```rust
use serde::Deserialize;
use toni::{FromContext, HttpContext};
use toni::extractors::Query;

pub struct Pagination {
    pub page: u32,
    pub per_page: u32,
    pub offset: u32,
}

impl FromContext<HttpContext> for Pagination {
    type Error = String;

    async fn extract(ctx: &HttpContext) -> Result<Self, Self::Error> {
        #[derive(Deserialize, Default)]
        struct RawPagination {
            page: Option<u32>,
            per_page: Option<u32>,
        }

        let Query(raw) = Query::<RawPagination>::extract(ctx)
            .await
            .map_err(|e| e.to_string())?;

        let page = raw.page.unwrap_or(1).max(1);
        let per_page = raw.per_page.unwrap_or(20).min(100);
        let offset = (page - 1) * per_page;

        Ok(Pagination { page, per_page, offset })
    }
}

#[get("/")]
fn list(&self, pagination: Pagination) -> Body {
    let items = self.service.find_page(pagination.offset, pagination.per_page);
    Body::json(serde_json::json!({
        "items": items,
        "page": pagination.page,
        "per_page": pagination.per_page,
    }))
}
```

The same composition builds aggregate extractors — an `AuthContext` combining a `BearerToken`, a client IP, and a user agent into one parameter is three `extract` calls on the same context.

## Body extractors

An extractor that reads the body starts with `take_body`, and its error type wraps your own in `BodyExtractionError` so the already-read case has somewhere to go:

```rust
use std::fmt;
use serde::de::DeserializeOwned;
use toni::{FromContext, HttpContext, take_body};
use toni::extractors::BodyExtractionError;

/// Deserializes the body as YAML (via the `serde_yaml` crate).
pub struct Yaml<T>(pub T);

#[derive(Debug)]
pub struct YamlError(String);

impl fmt::Display for YamlError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "{}", self.0)
    }
}

impl<T: DeserializeOwned + Send> FromContext<HttpContext> for Yaml<T> {
    type Error = BodyExtractionError<YamlError>;

    async fn extract(ctx: &HttpContext) -> Result<Self, Self::Error> {
        let req = take_body::<Self>(ctx)?;

        let (_parts, body) = req.into_parts();
        let bytes = body.collect().await.map_err(|e| {
            BodyExtractionError::Extract(YamlError(format!("Failed to read body: {e}")))
        })?;
        let value = serde_yaml::from_slice(&bytes).map_err(|e| {
            BodyExtractionError::Extract(YamlError(format!("Invalid YAML: {e}")))
        })?;

        Ok(Yaml(value))
    }
}
```

`take_body::<Self>(ctx)?` yields the owned `HttpRequest` — parts plus body — exactly once per request. When something earlier in the handler already took it, `take_body` returns a `BodyAlreadyRead` naming your extractor, which `?` lifts into `BodyExtractionError::AlreadyRead`. Your own failures go through `BodyExtractionError::Extract`.

### The one-body rule is a runtime check here

For the built-in body extractors, a handler with two body readers is a compile error — the controller macro recognizes them by type name and rejects the signature. It cannot recognize your types: custom extractors are exempt from that check, several of them may share a handler, and nothing at compile time records whether one of them reads the body.

So for custom extractors the rule holds at runtime instead. A custom body extractor beside `Json<T>` — or beside another custom body extractor — compiles, and the second one to run gets `BodyAlreadyRead`: the client receives the standard 400, and the error is also logged at `error` level naming the extractor, because the request was well-formed and the fault is the handler's signature.

By the same token, a metadata extractor's body-freedom is a convention, not a compile-time guarantee — nothing stops an impl from calling `take_body` while presenting as a header reader. Keep body reads out of extractors that claim to be metadata.

## Validation support

`Validated<E>` works with any extractor `E: FromContext<HttpContext> + ValidatableExtractor`. The second trait exposes the inner value for the `validator` crate:

```rust
pub trait ValidatableExtractor {
    type Inner: validator::Validate;

    fn get_inner(&self) -> &Self::Inner;
}
```

Implement it on your extractor to opt in:

```rust
use toni::extractors::ValidatableExtractor;

impl<T: validator::Validate> ValidatableExtractor for Yaml<T> {
    type Inner = T;

    fn get_inner(&self) -> &Self::Inner {
        &self.0
    }
}

// Now this validates the deserialized value before the handler runs:
// Validated(Yaml(dto)): Validated<Yaml<CreateUserDto>>
```

On failure, `Validated` produces `ValidationError` (exported alongside `ValidatableExtractor` from `toni::extractors`): `ExtractionError` when the inner extractor failed, `ValidationFailed` carrying the `validator::ValidationErrors` when a rule was violated. Both surface as the standard 400 extraction response.

## Other transports

`FromContext` is not HTTP-specific. A WebSocket or RPC extractor is the same trait implemented against `WsContext` or `RpcContext`, and an impl against one context makes the type a valid parameter for that transport's handlers only — using it anywhere else is a trait-bound error.
