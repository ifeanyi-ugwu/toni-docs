## Prerequisites

- Rust 1.85 or later (the crates use the 2024 edition)
- Cargo

## Option A — Start from a template with the CLI

The fastest way to get a working Toni project is through the CLI:

```bash
cargo install toni-cli
toni new my_app
cd my_app
cargo run
```

This scaffolds a project with `AppModule`, `AppController`, and `AppService` wired together and ready to run. See [CLI Commands](/docs/cli/commands) for the exact layout it generates.

## Option B — Add to an existing project

Add the core crate and exactly one HTTP adapter. The Toni API is identical
across all five — controllers, guards, interceptors, extractors, and global
middleware behave the same. What differs is the runtime attribute, the server
crate, and a handful of capabilities.

<Tabs items={['Axum', 'Actix', 'Salvo', 'Poem', 'Rocket']}>

<Tab value="Axum">

```toml title="Cargo.toml"
[dependencies]
toni = "0.2"
toni-axum = "0.1"
tokio = { version = "1", features = ["full"] }
```

```rust title="src/main.rs"
use toni::ToniFactory;
use toni_axum::AxumAdapter;

#[tokio::main]
async fn main() {
    let mut app = ToniFactory::create(AppModule).await.unwrap();
    app.use_http_adapter(AxumAdapter::new(), ("127.0.0.1", 3000)).unwrap();
    app.start().await.unwrap();
}
```

The default. Streaming bodies both ways, and WebSocket on the HTTP port or its own.

</Tab>

Two more crates are needed by nearly every application:

```toml title="Cargo.toml"
[dependencies]
serde = { version = "1", features = ["derive"] }
serde_json = "1"
```

The `toni` crate's default `logger` feature installs a `tracing` subscriber at
startup, so an application logs to stderr with no setup — `default-features = false`
compiles it out. See [Logging](/docs/techniques/logging).

### Optional crates

| Crate | Purpose |
|-------|---------|
| `toni-config` | Environment-based configuration with optional validation |
| `toni-async-graphql` | GraphQL via `async-graphql` |
| `toni-juniper` | GraphQL via `juniper` |

That is the whole of `main`. Modules, controllers, and services live in your own
code and are wired together by the container at startup. To compare the adapters
in detail before committing to one, see [HTTP Adapters](/docs/http-adapters).

<FromNest>
`ToniFactory::create(AppModule)` takes the root module like `NestFactory.create`,
but there is no `app.listen(3000)` and no `app.init()`. The HTTP server is chosen
separately, by `use_http_adapter` — that call is also what registers the routes.
Startup is three phases: `create` resolves the dependency graph, `bind` acquires
the sockets, `run` serves. `start()` is `bind` plus `run`.
</FromNest>
