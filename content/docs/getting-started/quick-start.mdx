This guide walks through building a small REST API with a user resource. By the end you'll have a running server with a controller, a service, and proper module wiring.

## Project setup

Scaffold a project with the CLI, then add serde for the data types in this guide:

```bash
toni new users_api
cd users_api
cargo add serde --features derive
cargo add serde_json
```

`toni new` generates `src/main.rs` plus an `src/app/` directory holding the root module, a controller, and a service (see [Project Structure](/docs/getting-started/project-structure)). The next three steps replace the generated `app.service.rs`, `app.controller.rs`, and `app.module.rs` with the user resource.

## 1. Define a service

Services hold business logic. The `#[injectable]` attribute sits on the struct and registers it with the DI container; methods live in a plain `impl` block.

```rust
// src/app/app.service.rs
use serde::Serialize;
use toni::*;

#[derive(Clone, Serialize)]
pub struct User {
    pub id: u32,
    pub name: String,
    pub email: String,
}

#[injectable]
pub struct UserService;

impl UserService {
    pub fn find_all(&self) -> Vec<User> {
        vec![
            User { id: 1, name: "Alice".into(), email: "alice@example.com".into() },
            User { id: 2, name: "Bob".into(), email: "bob@example.com".into() },
        ]
    }

    pub fn find_one(&self, id: u32) -> Option<User> {
        self.find_all().into_iter().find(|u| u.id == id)
    }
}
```

<Bridge>
In NestJS you'd write:

```ts
@Injectable()
export class UserService {
  findAll(): User[] { /* ... */ }
  findOne(id: number): User | undefined { /* ... */ }
}
```

`#[injectable]` is the direct counterpart to `@Injectable()`. It goes on a plain struct definition — the `impl` block stays an ordinary Rust `impl`, same as any struct.
</Bridge>

## 2. Define a controller

Controllers map HTTP routes to methods. `#[controller]` takes a base path and sits on the struct; dependencies are `#[inject]` fields. Route handlers live in a separate `impl` block marked `#[routes]`, with each method annotated by its HTTP verb and sub-path.

```rust
// src/app/app.controller.rs
use serde::Deserialize;
use toni::extractors::{Json, Path};
use toni::*;

use super::app_service::UserService;

#[derive(Deserialize)]
pub struct CreateUserDto {
    pub name: String,
    pub email: String,
}

#[controller("/users")]
pub struct UserController {
    #[inject]
    service: UserService,
}

#[routes]
impl UserController {
    #[get("/")]
    fn find_all(&self) -> Body {
        Body::json(serde_json::json!(self.service.find_all()))
    }

    #[get("/{id}")]
    fn find_one(&self, Path(id): Path<u32>) -> HttpResponse {
        match self.service.find_one(id) {
            Some(user) => HttpResponse::ok().json(serde_json::json!(user)).build(),
            None => HttpResponse::not_found().build(),
        }
    }

    #[post("/")]
    fn create(&self, Json(dto): Json<CreateUserDto>) -> HttpResponse {
        HttpResponse::created()
            .json(serde_json::json!({ "name": dto.name, "email": dto.email }))
            .build()
    }
}
```

`Body::json` and the `HttpResponseBuilder::json` method both take a `serde_json::Value` — wrap serializable types with `serde_json::json!(...)` (or `serde_json::to_value`).

<Bridge>
The NestJS equivalent:

```ts
@Controller('users')
export class UserController {
  constructor(private readonly service: UserService) {}

  @Get()
  findAll() { return this.service.findAll(); }

  @Get(':id')
  findOne(@Param('id') id: string) { /* ... */ }

  @Post()
  create(@Body() dto: CreateUserDto) { /* ... */ }
}
```

Key differences: `#[inject]` fields replace constructor injection. `Path<u32>` replaces `@Param('id')` — path segments use `{id}` syntax, not `:id`. `Json<T>` replaces `@Body()`. The `#[routes]` impl block is what Toni scans for `#[get]`/`#[post]` handlers.
</Bridge>

## 3. Wire up the module

Modules declare which controllers and services belong together. The generated `app.module.rs` already defines the root module — point it at the new types:

```rust
// src/app/app.module.rs
use toni::*;

use super::app_controller::UserController;
use super::app_service::UserService;

#[module(
  imports: [],
  controllers: [UserController],
  providers: [UserService],
  exports: []
)]
impl AppModule {}
```

As the application grows, features get their own modules listed under `imports:` — `toni generate resource <name>` scaffolds and wires one in a single step.

<Bridge>
```ts
// NestJS
@Module({
  controllers: [UserController],
  providers: [UserService],
})
export class AppModule {}
```

Direct mapping. `#[module]` accepts `imports`, `controllers`, `providers`, and `exports`, and can sit on an empty `impl` block (as generated by the CLI) or a unit struct — `#[module(...)] pub struct AppModule;` works the same.
</Bridge>

## 4. Start the server

The generated `src/main.rs` needs no changes:

```rust
// src/main.rs
use app::app_module::AppModule;
use toni::ToniFactory;
use toni_axum::AxumAdapter;

mod app;

#[tokio::main]
async fn main() {
    let mut app = ToniFactory::new()
        .create_with(AppModule)
        .await;

    app.use_http_adapter(AxumAdapter::new(), 3000, "127.0.0.1")
        .unwrap();

    app.start().await.unwrap();
}
```

`ToniFactory::create(AppModule)` is a shorthand for `ToniFactory::new().create_with(AppModule)` — use the explicit form when registering global guards, interceptors, or middleware on the factory first.

Run it:

```bash
cargo run
```

Your API is now live:

```bash
curl http://localhost:3000/users
# [{"id":1,"name":"Alice","email":"alice@example.com"},...]

curl http://localhost:3000/users/1
# {"id":1,"name":"Alice","email":"alice@example.com"}

curl -X POST http://localhost:3000/users \
  -H "Content-Type: application/json" \
  -d '{"name":"Carol","email":"carol@example.com"}'
# {"name":"Carol","email":"carol@example.com"}
```

## What happens at startup

When `create_with` (or `create`) is called, Toni:

1. Scans the module tree starting from `AppModule`
2. Builds a dependency graph from all declared providers and controllers
3. Instantiates everything in dependency order
4. Runs `on_module_init` hooks

Then `use_http_adapter` registers every route from the module tree with the adapter, and `start()` runs `on_application_bootstrap` hooks, binds the socket, and serves until shutdown.
