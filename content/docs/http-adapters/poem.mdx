The `toni-poem` crate wraps [Poem](https://crates.io/crates/poem) 3.1 to handle HTTP for Toni applications. It implements both `HttpAdapter` and `WebSocketAdapter`, so a single adapter type covers HTTP routes, same-port WebSocket upgrades, and separate-port WebSocket servers. Bodies stream in both directions.

## Installation

```toml
[dependencies]
toni = "0.2"
toni-poem = "0.1"
tokio = { version = "1", features = ["full"] }
```

## Basic setup

```rust
use toni::*;
use toni_poem::PoemAdapter;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let mut app = ToniFactory::new().create_with(AppModule).await;
    app.use_http_adapter(PoemAdapter::new(), ("127.0.0.1", 3000)).unwrap();
    app.start().await?;
    Ok(())
}
```

Toni and Poem agree on `:param` path syntax, so routes pass through unchanged — no rewrite step. Every standard method has a direct mapping (`GET` through `TRACE` and `CONNECT`), so dispatch is exact-match. A `*toni_fallback` wildcard catches unmatched paths and returns Toni's standard 404 envelope through the global middleware chain.

## WebSocket support

Same-port gateways (`#[websocket_gateway("/path")]`) upgrade on the HTTP listener automatically. Separate-port gateways (`port = N`) need a second instance registered as the WebSocket adapter:

```rust
app.use_http_adapter(PoemAdapter::new(), ("127.0.0.1", 3000)).unwrap();
app.use_websocket_adapter(PoemAdapter::new()).unwrap();
```

`port = 0` lets the OS assign a distinct listener. Sub-protocols are negotiated by echoing the first protocol the client offers in `Sec-WebSocket-Protocol`.

## Streaming bodies

Poem's `Body` is a thin newtype around the same `http-body` family Toni uses internally, so the bridge is nearly free in both directions:

- **Requests** are handed through unbuffered. `BodyStream` sees frames as they arrive; `Bytes`, `Json`, and friends collect on demand.
- **Responses** built with `Body::stream(...)` reach the client chunk by chunk, so [SSE](/docs/techniques/sse) and long-lived streaming responses work without buffering.

## Graceful shutdown

Poem exposes `run_with_graceful_shutdown` natively; the adapter feeds Toni's shutdown signal into it, and the HTTP server and any separate-port WebSocket servers stop in response to the same signal. Trigger it via the application's [`shutdown_handle()`](/docs/deployment/production#graceful-shutdown) — the framework installs no signal handlers of its own.
