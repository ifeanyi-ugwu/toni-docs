title: NATS Adapter

---

The NATS adapter maps each RPC pattern to a NATS subject. Request-response uses NATS's built-in reply-to inbox; fire-and-forget uses plain `publish`. A NATS server must be reachable from both sides.

## Server setup

Add the dependencies:

```toml
[dependencies]
toni = "0.2"
toni-nats = "0.1"
```

Register the adapter:

```rust
use toni::ToniFactory;
use toni_nats::NatsAdapter;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let mut app = ToniFactory::create(AppModule).await?;
    app.use_rpc_adapter(NatsAdapter::new("nats://127.0.0.1:4222"))?;
    app.start().await?;
    Ok(())
}
```

The initial connection retries until the server is reachable (`retry_on_initial_connect`), so a slow-starting NATS container does not kill the process. If the connection or a subject subscription ultimately fails, the failure surfaces from `app.bind()` (or `app.start()`) as `StartupError::Adapter { transport: "rpc", .. }`. Connection state changes (connected, disconnected, server errors) are logged.

## Multiple servers

`NatsAdapter::new` and `NatsClientTransport::new` accept anything implementing `IntoNatsServers` — a single URL, a `Vec<String>` / `Vec<&str>`, or a fixed-size array:

```rust
NatsAdapter::new("nats://127.0.0.1:4222")
NatsAdapter::new(["nats://node1:4222", "nats://node2:4222", "nats://node3:4222"])
NatsAdapter::new(vec!["nats://node1:4222".to_string(), "nats://node2:4222".to_string()])
```

## How patterns map to subjects

Each `#[message_pattern("x.y")]` or `#[event_pattern("x.y")]` subscribes to subject `x.y`. Routing is exact: the dispatcher matches the received message's subject against the registered pattern strings. NATS wildcards (`*`, `>`) in a pattern create a valid subscription, but messages arriving on it carry their concrete subject and find no exact-match handler — they fail with `not_found`. Register one handler per concrete subject.

## Wire behavior

- **Inbound payload** — parsed as JSON into `RpcData::Json`; anything that is not valid JSON becomes `RpcData::Binary`.
- **Headers** — NATS headers on the inbound message become `ctx.headers()`; per-call headers from `RpcClient::request(...).header(...)` travel as NATS headers.
- **Request-response** — a message with a reply-to inbox gets its reply published there. A reply-to that addresses an `#[event_pattern]` handler gets a `{"response": null}` ack.
- **Fire-and-forget** — no reply-to, nothing published back.

Reply framing:

```json
{"response": {"orderId": 1001}}
```

`RpcData::Text` replies wrap as a JSON string (`{"response": "pong"}`). `RpcData::Binary` replies are published **raw**, with no envelope — the only transport payload shape that round-trips binary unmodified.

Handler errors arrive inside `response` as the canonical envelope; dispatch failures arrive as `{"err": {"message": ..., "status": ...}}` with the lowercase statuses `not_found` / `forbidden` / `error`. See [Errors on the wire](/docs/microservices/rpc-controllers#errors-on-the-wire).

Test with the NATS CLI:

```bash
nats req order.create '{"item":"keyboard","qty":3}'   # request-response
nats pub order.shipped '{"order_id":1001}'            # fire-and-forget
```

## Client transport

```rust
use toni::{provider_value, RpcClient};
use toni_nats::NatsClientTransport;

provider_value!(
    "INVENTORY_CLIENT",
    RpcClient::new(NatsClientTransport::new("nats://127.0.0.1:4222"))
)
```

The connection is established lazily on the first `send` or `emit`; reconnection after a drop is handled by the NATS client library. `close()` flushes pending publishes.

### Custom timeout

Default request-response timeout is 5 seconds:

```rust
use std::time::Duration;

RpcClient::new(
    NatsClientTransport::new("nats://127.0.0.1:4222")
        .with_timeout(Duration::from_secs(15))
)
```

## Operational limits

Unlike the TCP/UDP adapters, the NATS adapter has no drain timeout, no `with_max_inflight` backpressure cap, and no bound local address (`BoundAdapters.rpc` is `None`) — each inbound message spawns an unbounded task, and shutdown does not wait for in-flight handlers. There is no per-request `rpc.request` tracing span either. Broker-side limits (max payload, slow-consumer handling) apply as configured on the NATS server.

## Combining HTTP and NATS

```rust
use toni_axum::AxumAdapter;
use toni_nats::NatsAdapter;

let mut app = ToniFactory::create(AppModule).await?;
app.use_http_adapter(AxumAdapter::new(), ("0.0.0.0", 3000))?;
app.use_rpc_adapter(NatsAdapter::new("nats://127.0.0.1:4222"))?;
app.start().await?;
```

Both transports share the same DI container and run concurrently inside `start()`. A worked HTTP-controller-calls-RPC example lives in the repository at `examples/rpc_nats_client.rs`.
