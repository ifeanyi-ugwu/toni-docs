---
title: Interceptors
description: Interceptors wrap route handlers — they run before and after, and can transform or short-circuit.
---

An interceptor wraps a route handler. Code before `next.run(context).await` runs before the handler; code after it runs once the handler (and any inner interceptors) has set the response. Skipping the `next.run` call short-circuits the chain entirely — useful for caching, circuit breakers, and canned responses.

Like guards and pipes, interceptors are generic over the per-request context: `Interceptor<HttpContext>` runs on HTTP routes, `Interceptor<RpcContext>` on RPC patterns, `Interceptor<WsContext>` on WebSocket messages, `Interceptor<GrpcContext>` on gRPC methods.

<Bridge>
Toni interceptors map to NestJS's `NestInterceptor`. `intercept` receives the context and a `next`; calling `next.run(context).await` proceeds to the handler. Instead of RxJS operators on an observable, code placed after the `next.run` call is the response side.
</Bridge>

## The Interceptor trait

```rust
use toni::async_trait;
use toni::context::HandlerContext;

#[async_trait]
pub trait InterceptorNext<C: ?Sized + HandlerContext>: Send {
    async fn run(self: Box<Self>, context: &mut C);
}

#[async_trait]
pub trait Interceptor<C: ?Sized + HandlerContext>: Send + Sync {
    async fn intercept(&self, context: &mut C, next: Box<dyn InterceptorNext<C>>);
}
```

Both live at `toni::traits_helpers::{Interceptor, InterceptorNext}`. `run` consumes `Box<Self>`, so the downstream chain can be invoked at most once — the type system rules out calling the handler twice.

## Timing interceptor

```rust
use std::time::Instant;
use toni::async_trait;
use toni::context::HttpContext;
use toni::traits_helpers::{Interceptor, InterceptorNext};

pub struct TimingInterceptor;

#[async_trait]
impl Interceptor<HttpContext> for TimingInterceptor {
    async fn intercept(&self, ctx: &mut HttpContext, next: Box<dyn InterceptorNext<HttpContext>>) {
        let start = Instant::now();
        next.run(ctx).await;
        println!("request took {:?}", start.elapsed());
    }
}
```

## Reading the request, inspecting the response

On `HttpContext`, the request is available before `next.run` via `ctx.request()` (`&RequestPart` — method, URI, headers). After `next.run`, the response set by the handler is available via `ctx.response()`:

```rust
pub struct AuditInterceptor;

#[async_trait]
impl Interceptor<HttpContext> for AuditInterceptor {
    async fn intercept(&self, ctx: &mut HttpContext, next: Box<dyn InterceptorNext<HttpContext>>) {
        let method = ctx.request().method.clone();
        let uri = ctx.request().uri.clone();

        next.run(ctx).await;

        let status = ctx.response().map(|r| r.status).unwrap_or(0);
        println!("{method} {uri} -> {status}");
    }
}
```

`HttpResponse` exposes `status` (a public `u16` field), `headers` (`Vec<(String, String)>`), and `body`.

## Transforming the response

`ctx.response_mut()` gives mutable access to the response after the handler ran; `ctx.set_response(...)` replaces it wholesale:

```rust
use toni::HttpResponse;

pub struct CacheHeaderInterceptor;

#[async_trait]
impl Interceptor<HttpContext> for CacheHeaderInterceptor {
    async fn intercept(&self, ctx: &mut HttpContext, next: Box<dyn InterceptorNext<HttpContext>>) {
        next.run(ctx).await;

        if let Some(response) = ctx.response_mut() {
            if response.status == 200 {
                response
                    .headers
                    .push(("Cache-Control".into(), "max-age=60".into()));
            }
        }
    }
}
```

## Short-circuiting

Not calling `next.run` skips everything downstream — inner interceptors, pipes, and the handler. Set a response before returning so the client gets a reply:

```rust
use std::sync::atomic::{AtomicBool, Ordering};
use serde_json::json;
use toni::HttpResponse;

pub struct MaintenanceInterceptor {
    pub enabled: AtomicBool,
}

#[async_trait]
impl Interceptor<HttpContext> for MaintenanceInterceptor {
    async fn intercept(&self, ctx: &mut HttpContext, next: Box<dyn InterceptorNext<HttpContext>>) {
        if self.enabled.load(Ordering::Relaxed) {
            ctx.set_response(
                HttpResponse::builder()
                    .status(503)
                    .json(json!({ "message": "Down for maintenance" }))
                    .build(),
            );
            return; // handler is skipped
        }
        next.run(ctx).await;
    }
}
```

## Passing data to the handler

The context's typed extensions bag carries values between enhancers and handlers without coupling their types:

```rust
#[derive(Clone)]
pub struct RequestId(pub String);

#[async_trait]
impl Interceptor<HttpContext> for RequestIdInterceptor {
    async fn intercept(&self, ctx: &mut HttpContext, next: Box<dyn InterceptorNext<HttpContext>>) {
        ctx.extensions_mut().insert(RequestId(new_id()));
        next.run(ctx).await;
    }
}
```

Downstream enhancers read it back with `ctx.extensions().get::<RequestId>()`.

## DI-aware interceptors

Declare the interceptor as an `#[injectable]` provider and implement the trait — no marker attribute. List it in the module's `providers` and apply it by bare type name:

```rust
use toni::injectable;

#[injectable]
pub struct WsLoggingInterceptor;

#[async_trait]
impl Interceptor<WsContext> for WsLoggingInterceptor {
    async fn intercept(&self, ctx: &mut WsContext, next: Box<dyn InterceptorNext<WsContext>>) {
        println!("client={} event={}", ctx.client().id, ctx.event());
        next.run(ctx).await;
        println!("message processed");
    }
}
```

```rust
#[module(
    providers: [ChatGateway, WsLoggingInterceptor],
    imports: [BroadcastModule::new()],
)]
struct ChatModule;
```

Dependencies work the same as any provider: `#[inject]` fields plus a `#[new]` constructor.

## Applying interceptors

### Controller level

`#[use_interceptors]` goes on the `#[routes]` impl block (or `#[patterns]` / `#[subscriptions]` / `#[grpc_methods]` for the other transports):

```rust
#[controller("/users")]
pub struct UsersController {}

#[routes]
#[use_interceptors(TimingInterceptor {}, CacheHeaderInterceptor {})]
impl UsersController {
    // all routes are wrapped by both interceptors
}
```

### Method level

```rust
#[routes]
impl ItemsController {
    #[use_interceptors(TimingInterceptor {})]  // only this route is timed
    #[get("/:id")]
    fn find_one(&self) -> Body { /* ... */ }
}
```

Bare type names resolve from DI (`#[use_interceptors(WsLoggingInterceptor)]`); expressions instantiate directly (`#[use_interceptors(TimingInterceptor {})]`).

### Global (per transport)

```rust
use std::sync::Arc;

let mut factory = ToniFactory::new();
factory.use_global_http_interceptors(Arc::new(TimingInterceptor));
```

`use_global_rpc_interceptors` and `use_global_ws_interceptors` register for the other transports.

## Execution order

Interceptors nest as onion layers, global outermost, method innermost:

```
Global (before) → Controller (before) → Method (before) → Pipes → Handler
Handler → Method (after) → Controller (after) → Global (after)
```

A panic inside an interceptor is caught by the framework and routed through the error pipeline instead of tearing down the request — see [Error Handling](/docs/request-lifecycle/error-handling).
