---
title: Pipes
description: Pipes transform and validate the request context right before the route handler runs.
---

A pipe is a synchronous hook that runs after guards and interceptors, immediately before the handler. It inspects the per-request context and may answer the request by returning `Some(response)`; `None` passes the request through. A pipe can also attach data for the handler via extensions.

For parsing and validating request data, pipes are rarely the right tool in Toni — extractors and `Validated<T>` cover those cases at the type level. Pipes exist for genuinely cross-cutting transformations applied to many routes regardless of their body types.

## The Pipe trait

```rust
use toni::context::HandlerContext;

pub trait Pipe<C: ?Sized + HandlerContext, R>: Send + Sync {
    fn process(&self, data: &C) -> Option<R>;
}
```

Import it from `toni::traits_helpers::Pipe`. `process` is **sync** — no async work inside a pipe. Like the other enhancer traits it is generic over the context and the transport's answer type `R`: `Pipe<HttpContext, HttpResponse>`, `Pipe<RpcContext, RpcHandlerResult>`, `Pipe<WsContext, WsHandlerResult>`. gRPC methods run guards, interceptors, and error handlers, but not pipes.

## Validation belongs to extractors

The common validation case is handled by the `Validated<T>` extractor (see [Built-in Extractors](/docs/extractors/built-in)) — no pipe involved:

```rust
use serde::Deserialize;
use toni::extractors::{Json, Validated};
use validator::Validate;

#[derive(Debug, Deserialize, Validate)]
struct CreateProductDto {
    #[validate(length(min = 3, message = "Name must be at least 3 characters"))]
    name: String,

    #[validate(range(min = 0.0, message = "Price cannot be negative"))]
    price: f64,

    #[validate(email(message = "Invalid email format"))]
    contact_email: String,
}

#[controller("/api")]
pub struct ProductsController;

#[routes]
impl ProductsController {
    #[post("/products")]
    fn create(&self, Validated(Json(dto)): Validated<Json<CreateProductDto>>) -> Body {
        // dto is validated — invalid input was rejected with a 400 before this runs
        Body::json(serde_json::json!({ "name": dto.name, "price": dto.price }))
    }
}
```

Type parsing works the same way: `Path<i32>` parses `"42"` into `42` and rejects `"abc"` with a 400 — no `ParseIntPipe` equivalent needed.

<FromNest>
There is no global `ValidationPipe` to register, and registering an equivalent is
usually the wrong move. NestJS needs one because TypeScript types are gone at
runtime. In Toni `Path<i32>` already parses and `Validated<Json<T>>` already
validates, both visible in the handler signature and enforced by the compiler.
`Pipe` covers what extractors cannot express — a check that needs a dependency,
or one that spans several extracted values.
</FromNest>

## A rejecting pipe

A pipe stops a request by returning `Some(response)`. Remaining pipes and the handler are skipped, and the returned response is sent:

```rust
use toni::context::{HandlerContext, HttpContext};
use toni::http_helpers::{Body, HttpResponse};
use toni::traits_helpers::Pipe;

pub struct RequireValidHeaderPipe;

impl Pipe<HttpContext, HttpResponse> for RequireValidHeaderPipe {
    fn process(&self, context: &HttpContext) -> Option<HttpResponse> {
        let is_invalid = context
            .request()
            .headers
            .get("x-valid")
            .and_then(|v| v.to_str().ok())
            .map(|value| value == "false")
            .unwrap_or(false);

        if is_invalid {
            let mut response = HttpResponse::new();
            response.status = 400;
            response.body = Some(Body::text("Validation failed".to_string()));
            return Some(response);
        }
        None
    }
}
```

## A transforming pipe

The request parts are read-only through the context, so pipes hand data downstream through the typed extensions bag:

```rust
#[derive(Clone)]
pub struct ClientRegion(pub String);

pub struct RegionPipe;

impl Pipe<HttpContext, HttpResponse> for RegionPipe {
    fn process(&self, context: &HttpContext) -> Option<HttpResponse> {
        let region = context
            .request()
            .headers
            .get("cf-ipcountry")
            .and_then(|v| v.to_str().ok())
            .unwrap_or("unknown")
            .to_string();
        context.extensions().insert(ClientRegion(region));
        None
    }
}
```

## DI-aware pipes

Declare an `#[injectable]` provider, implement `Pipe<C>`, list it in `providers` — the role is detected from the trait impl, no marker attribute:

```rust
use toni::injectable;
use toni::traits_helpers::Pipe;

#[injectable]
pub struct SanitizationPipe {
    #[inject]
    sanitizer: SanitizerService,
}

impl SanitizationPipe {
    #[new]
    pub fn new(sanitizer: SanitizerService) -> Self {
        Self { sanitizer }
    }
}

impl Pipe<HttpContext, HttpResponse> for SanitizationPipe {
    fn process(&self, context: &HttpContext) -> Option<HttpResponse> {
        self.sanitizer.clean(context);
        None
    }
}
```

## Applying pipes

### Method level

```rust
#[routes]
impl PostsController {
    #[use_pipes(RequireValidHeaderPipe {})]
    #[post("")]
    fn create(&self, Json(dto): Json<CreatePostDto>) -> Body { /* ... */ }
}
```

### Controller level

`#[use_pipes]` on the `#[routes]` impl (or `#[patterns]` / `#[subscriptions]`) applies to every handler in it:

```rust
#[routes]
#[use_pipes(SanitizationPipe)]   // bare name → resolved from DI
impl UsersController { /* ... */ }
```

### Global (per transport)

```rust
use std::sync::Arc;

let mut factory = ToniFactory::new();
factory.use_global_http_pipes(Arc::new(RegionPipe));
```

`use_global_rpc_pipes` and `use_global_ws_pipes` register for the other transports.

Pipes run in scope order — global, controller, method — and within each scope in the order listed. A pipe that returns `Some` answers the request; later pipes and the handler are skipped. A panic inside a pipe is caught and routed through the error pipeline as a `PanicRecovered` event (see [Error Handling](/docs/request-lifecycle/error-handling)).

## Extractors vs pipes

| Concern | Reach for |
|---------|-----------|
| Parse a path/query param into a typed value | `Path<T>` / `Query<T>` — serde does it |
| Validate a request body | `Validated<Json<T>>` + `validator` derive |
| Default values for missing params | `Option<T>` or `#[serde(default)]` |
| Per-field transformation (trim, normalize) | `#[serde(deserialize_with = ...)]` |
| The same check or annotation across many routes | A pipe |
| Reject requests based on request-wide state | A pipe (or a guard, if it's authorization) |
