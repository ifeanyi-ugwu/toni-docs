---
title: Server-Sent Events
description: Stream events from server to client over a persistent HTTP connection.
---

Server-Sent Events (SSE) let you push a stream of events to the browser over a single long-lived HTTP response. Toni provides `SseEvent` to build individual events and `sse()` / `Sse::new()` to wrap a stream into an HTTP response.

## Basic usage

Return `sse(stream)` from any handler. The stream yields `SseEvent` values:

```rust
use futures::stream;
use toni::{sse, SseEvent};

#[get("/events")]
async fn events(&self) -> impl IntoResponse {
    let s = stream::iter([
        SseEvent::data("hello").event("greet"),
        SseEvent::data("world").id("2"),
    ]);
    sse(s)
}
```

Toni sets `Content-Type: text/event-stream`, `Cache-Control: no-cache`, and `X-Accel-Buffering: no` automatically.

## Building events

```rust
SseEvent::data("the payload")       // required
    .event("named-event")           // optional — client listens with addEventListener
    .id("42")                       // optional — browser sends back as Last-Event-ID on reconnect
    .retry_ms(3000)                 // optional — reconnect delay hint in milliseconds
```

Only `data` is required. Multi-line data is split into multiple `data:` lines per the SSE spec.

## Live counter example

```rust
use std::time::Duration;
use futures::stream;
use toni::{sse, SseEvent};

#[get("/counter")]
async fn counter(&self) -> impl IntoResponse {
    let s = stream::unfold(0u32, |n| async move {
        tokio::time::sleep(Duration::from_secs(1)).await;
        Some((SseEvent::data(format!("count: {n}")).id(n.to_string()), n + 1))
    });
    sse(s)
}
```

## Fallible streams

Use `Sse::new` when your stream yields `Result<SseEvent, E>`. Any error type that implements `Into<Box<dyn Error + Send + Sync>>` works:

```rust
use toni::http_helpers::Sse;

#[get("/feed")]
async fn feed(&self) -> impl IntoResponse {
    let s = some_fallible_stream(); // Stream<Item = Result<SseEvent, MyError>>
    Sse::new(s)
}
```

`sse()` is a shorthand for infallible streams — it wraps each `SseEvent` in `Ok` before passing it to `Sse::new`.

## Service-level broadcaster

Inject a service that holds a `broadcast::Sender` to fan out to all connected clients:

```rust
use tokio::sync::broadcast;
use toni::{injectable, sse, SseEvent};

#[injectable(pub struct EventsService {
    tx: broadcast::Sender<String>,
})]
impl EventsService {
    pub fn new() -> Self {
        let (tx, _) = broadcast::channel(64);
        Self { tx }
    }

    pub fn emit(&self, data: String) {
        let _ = self.tx.send(data);
    }

    pub fn subscribe(&self) -> impl futures::Stream<Item = SseEvent> + Send + 'static {
        let rx = self.tx.subscribe();
        futures::stream::unfold(rx, |mut rx| async move {
            loop {
                match rx.recv().await {
                    Ok(data) => return Some((SseEvent::data(data), rx)),
                    Err(broadcast::error::RecvError::Lagged(_)) => continue,
                    Err(broadcast::error::RecvError::Closed) => return None,
                }
            }
        })
    }
}

#[controller("/sse", pub struct SseController {
    #[inject]
    events: EventsService,
})]
impl SseController {
    pub fn new(events: EventsService) -> Self { Self { events } }

    #[get("/live")]
    async fn live(&self) -> impl IntoResponse {
        sse(self.events.subscribe())
    }

    #[post("/emit")]
    async fn emit(&self, body: String) -> impl IntoResponse {
        self.events.emit(body);
        HttpResponse::no_content().build()
    }
}
```

## API reference

```rust
// Build an event
SseEvent::data(impl Into<String>) -> SseEvent
    .event(impl Into<String>) -> Self      // named event type
    .id(impl Into<String>) -> Self         // Last-Event-ID
    .retry_ms(u64) -> Self                 // reconnect delay hint (ms)

// Wrap a stream into an SSE response
sse<S: Stream<Item = SseEvent>>(stream: S) -> impl IntoResponse

// For fallible streams
Sse::new<S: Stream<Item = Result<SseEvent, E>>>(stream: S) -> impl IntoResponse
```
