Integration tests exercise the full application — modules, DI, lifecycle hooks, and HTTP routing — without mocking internal boundaries.

## Testing with the application context

`ToniFactory::create_application_context` creates a full DI-initialized context without starting an HTTP server. Use it to test service interactions end-to-end:

```rust
use toni::ToniFactory;

#[tokio::test]
async fn test_user_creation_flow() {
    let mut ctx = ToniFactory::create_application_context(AppModule).await.unwrap();

    let users_service = ctx.get::<UsersService>().await.unwrap();
    let orders_service = ctx.get::<OrdersService>().await.unwrap();

    // Create a user
    let user = users_service.create("Alice", "alice@example.com").await.unwrap();
    assert_eq!(user.name, "Alice");

    // Create an order for that user
    let order = orders_service.create_order(user.id, 49.99).await.unwrap();
    assert!(order.id > 0);
    assert_eq!(order.user_id, user.id);

    ctx.close().await;
}
```

`create_application_context` runs the full startup sequence, including `on_application_bootstrap`, and propagates hook failures as `Err` — the `.unwrap()` is what turns a broken startup into a test failure. `ctx.close()` runs the shutdown lifecycle hooks and returns `()` — there is no `Result` to unwrap.

## HTTP integration tests

For HTTP-level tests, start a real server and send requests with an HTTP client:

```toml title="Cargo.toml"
[dev-dependencies]
reqwest = { version = "0.12", features = ["json"] }
tokio = { version = "1", features = ["full"] }
```

Two framework facts shape the harness:

- The application is not `Send`, so it can't be moved into `tokio::spawn`. Drive it on a [`LocalSet`](https://docs.rs/tokio/latest/tokio/task/struct.LocalSet.html) with `spawn_local`.
- Passing port `0` to `use_http_adapter` lets the OS pick a free port. `app.bind().await` returns `BoundAdapters` with the real address once the socket is live — no sleeps, no free-port scanning, no conflicts between parallel tests.

A harness that wants to own the socket can also bind a `std::net::TcpListener` itself and pass it to `use_http_adapter` as a [bind target](/docs/techniques/bind-targets) — the address is then known before the app starts, with no port-0 handoff.

```rust
use std::net::SocketAddr;

use toni::{ModuleMetadata, ShutdownHandle, ToniFactory};
use toni_axum::AxumAdapter;

/// Spawns the app on the current LocalSet; returns its base URL and a
/// handle for graceful teardown. Call from inside a LocalSet.
async fn start_server(module: impl ModuleMetadata + 'static) -> (String, ShutdownHandle) {
    let (addr_tx, addr_rx) = tokio::sync::oneshot::channel::<SocketAddr>();
    let (shutdown_tx, shutdown_rx) = tokio::sync::oneshot::channel::<ShutdownHandle>();

    tokio::task::spawn_local(async move {
        let mut app = ToniFactory::create(module).await.unwrap();
        app.use_http_adapter(AxumAdapter::new(), ("127.0.0.1", 0)).unwrap();

        let bound = app.bind().await.unwrap();
        let _ = addr_tx.send(bound.http.expect("HTTP adapter not bound"));
        let _ = shutdown_tx.send(app.shutdown_handle());

        app.run().await;
    });

    let addr = addr_rx.await.unwrap();
    let shutdown = shutdown_rx.await.unwrap();
    (format!("http://{addr}"), shutdown)
}

#[tokio::test]
async fn test_get_users() {
    let local = tokio::task::LocalSet::new();
    local
        .run_until(async {
            let (base_url, shutdown) = start_server(TestModule).await;
            let client = reqwest::Client::new();

            let response = client
                .get(format!("{base_url}/users"))
                .send()
                .await
                .unwrap();

            assert_eq!(response.status(), 200);
            let users: Vec<serde_json::Value> = response.json().await.unwrap();
            assert!(!users.is_empty());

            // Graceful teardown: runs shutdown hooks, closes connections
            shutdown.shutdown();
            shutdown.completed().await;
        })
        .await;
}

#[tokio::test]
async fn test_create_user() {
    let local = tokio::task::LocalSet::new();
    local
        .run_until(async {
            let (base_url, shutdown) = start_server(TestModule).await;
            let client = reqwest::Client::new();

            let response = client
                .post(format!("{base_url}/users"))
                .json(&serde_json::json!({
                    "name": "Alice",
                    "email": "alice@test.com"
                }))
                .send()
                .await
                .unwrap();

            assert_eq!(response.status(), 201);
            let user: serde_json::Value = response.json().await.unwrap();
            assert_eq!(user["name"], "Alice");

            shutdown.shutdown();
            shutdown.completed().await;
        })
        .await;
}
```

Skipping the `shutdown.shutdown()` teardown is fine for pure request/response tests — the server task is dropped with the `LocalSet` — but shutdown-dependent assertions (lifecycle hooks, connection cleanup) need the explicit handle.

## Testing a specific module in isolation

Create a test-only module that provides only what you need:

```rust
#[module(
    controllers: [UsersController],
    providers: [
        UsersService,
        // Use a fake database service instead of the real one
        provide!("DB", FakeDatabase::new()),
    ],
)]
pub struct UsersTestModule;

#[tokio::test]
async fn test_users_controller() {
    let local = tokio::task::LocalSet::new();
    local
        .run_until(async {
            let (base_url, _shutdown) = start_server(UsersTestModule).await;
            // ... run HTTP tests against UsersController with fake dependencies
        })
        .await;
}
```

## Lifecycle hooks in tests

Lifecycle hooks run normally in integration tests. If `on_module_init` makes real network calls (database, cache), use test-specific provider implementations that avoid external systems.

## Asserting startup failures

Startup failures are returned values, not process exits, so a test can assert on them directly:

```rust
use toni::{StartupError, ToniFactory};

#[tokio::test]
async fn failing_init_hook_surfaces_from_create() {
    let result = ToniFactory::create(BadModule).await;

    assert!(matches!(result, Err(StartupError::HookFailed { .. })));
}
```

`on_module_init` failures come back from `create`; `on_application_bootstrap` failures from `bind` — or from `create_application_context`, which runs bootstrap itself. `StartupError` is `#[non_exhaustive]`: match variants with `..` as above, and keep a wildcard arm in any exhaustive `match`.

## Tip: test isolation

Port `0` means parallel tests never fight over ports. Serialize only when tests share external state (a database, a message broker):

```bash
cargo test -- --test-threads=1
```

or annotate the conflicting tests with the [`serial_test`](https://docs.rs/serial_test) crate and leave the rest parallel.
