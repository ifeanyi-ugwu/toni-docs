title: WebSocket
description: Gateways, rooms, and broadcasting — with the same DI container and enhancer chain as HTTP.
---

A gateway is the WebSocket counterpart of a controller: a struct with message handlers, resolved from the container, wrapped in the same guards and interceptors. Gateways run on the HTTP port by default, or on one of their own.

Two kinds of state matter here and are easy to confuse. Per-connection state belongs in the **session**, which lives as long as the client. Per-message state belongs in the context extensions — WebSocket request scope is one message, not one connection.
